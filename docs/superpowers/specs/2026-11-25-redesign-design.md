# pocoapoke デザイン一新 設計書

- 日付: 2026-11-25
- 対象リポジトリ: `Hiroki-Ko/pocoapoke`（React + Vite / Cloudflare Pages Functions / D1）
- モックアップ: https://claude.ai/artifact/9MAvK5QTxPoH3cdtsTYAjk （住みごこち・一覧・編集・登録の4画面。データは見本）

## 1. 目的と背景

pocoapoke は「ぽこあポケモン」で街に住むポケモンを管理する個人用Webアプリ。
主な利用シーンは **ゲームをしながらスマホで開き、ちょっとした確認とステータス更新をする** こと。

今の画面は表が横に広く、スマホでは横スクロールが必要で見づらい。名前だけでポケモンを判別するのも手間。
今回のゴールは、スマホで片手でさっと使える見やすい画面に作り直し、名前の横にポケモンのアイコンを表示すること。

### 代表的な使い方（ユーザーの言葉から）

**住みごこちの更新（最もよく使う）**
1. 「住んでる街」で絞り込み、「住みごこち」順に並べる（アプリ）
2. 住みごこちが低い順にポケモンのところへ行き、アクションを取る（ゲーム）
3. アクション後、または一通り回った後に、ゲーム内で住みごこちを確認し、アプリで修正する（アプリ）
4. 次の街へ移動し、1〜3を繰り返す

**引っ越し先の検討（一覧を使う）**
1. 進化ラインは同じ街で過ごす、そこに住んでいて違和感がないか、を意識して移動候補を選ぶ
2. 各街の住民数を確認し、移動で街ごとの数のバランスが崩れないか確認する
3. 好きな環境などを考慮して、適した街へ引っ越す
4. すみか作りで、好みの近いポケモンを近くに配置する（「好みが近い」＝好きなものがどれだけ重なるか。既に住んでいるポケモンと移動予定のポケモンに同じ好きなものがあるか）

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
- スマホ基準のデザイン（PCはその延長で中央寄せ）
- すべての画面で、名前の横にポケモンのアイコンを表示
- 住みごこち画面で「街で絞り込み → 低い順に回る → 修正」が最短の操作でできる
- その日のお世話チェックと欲しいもののメモが、ゲーム内の日付（毎朝4:00切り替え）でリセットされる
- 一覧で、住民数・好きな環境・好きなもの・似た好みのポケモンを確認できる
- ファビコンをメタモンに変更

### 非ゴール
- ゲームデータからの画像抽出（行わない。ゲーム内アイコンはユーザーが撮ったスクショから切り抜く）
- 一覧画面からの直接編集（一覧は見る専用。編集は編集画面で）
- ダークモード対応

### アンチゴール（技術的に動いても失敗とみなすもの）
- **欲しいものを選んで保存しただけで、お世話済みチェックが付くこと。** アイテムを取りに行くとき、誰用のメモか分からなくなる。チェックは □ を手動でタップしたときだけ付く。住みごこちを変更したときも自動では付けない。
- 誤タップでチェックが付き、外せない／外しても再読み込みで戻ること。
- 既存のD1データ（登録済みポケモン・ステータス）が失われること。
- スマホで横スクロールしないと情報が見られないこと。

## 3. 制約

- 技術構成は継続: React 19 + Vite / Cloudflare Pages Functions（`functions/api/*.ts`）/ D1（binding `DB`）。
- **スタイリングは MUI をやめて Tailwind CSS に切り替える**（ユーザー決定。§4参照）。`@mui/*`, `@emotion/*` は削除する。
- 本番D1には既存データがある。スキーマ変更は既存データを壊さない方法（列の追加）で行い、作業前に本番D1をバックアップする（`wrangler d1 export` など）。
- `.gitignore` に `public/` が含まれている（ただし `public/index.html` などは追跡されている）。`public/` に置く新しいファイル（アイコン・ファビコン）がコミットされるよう、`.gitignore` を調整するか強制追加すること。
- この作業環境からは `git push` ができない。push と本番反映はユーザーが手元のターミナルで行う（Cloudflare Pages は push で自動デプロイされている）。
- アプリは pages.dev で公開されているが、URLは共有しない前提（ユーザー確認済み）。

## 4. 作り方の案（検討した案と決定）

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A | MUIのまま、画面ごとに段階的にリリース | 早く使い始められる。1回の変更が小さい | しばらく新旧デザインが混在。MUIの上書きが多い |
| B | MUIのまま、まとめて1回でリリース | 新旧が混ざらない | MUIの「Googleっぽさ」を上書きする手間、アプリが重いまま |
| C | Tailwindに作り替える | モックの見た目をそのまま書ける。オシャボ管理アプリと書き方が揃う。アプリが軽くなる（現状 JS 512KB） | 導入作業と、通知・スイッチ等の小さい部品の自作が必要 |

**決定: B＋C（Tailwind に切り替え、画面はまとめて1回でリリース）。**
理由: 今回はほぼ全画面を作り直すため、Cの「書き直し」の追加コストは小さい。リリースが遅くなっても問題ない（ユーザー）。
進め方: **データ（DB列追加・API）の変更だけ先に本番へ出し**、画面は新しい4画面がそろってから一度に切り替える。
データ先行リリースでは、旧画面が動き続けるよう後方互換を保つこと（列追加のみ、既存APIの戻り値は壊さない）。

## 5. 決定事項（ユーザーが決めたもの）

### 5.1 共通
- 画面下にタブバー: 「一覧」「住みごこち」「登録」。
- ヘッダー: 上に小さくメタモンのアイコン＋「pocoapoke」、その下に大きな見出し（例: 「住みごこちチェック」「ポケモン一覧」「ポケモン編集」「ポケモン登録」）と一言の説明。黄色系のグラデーション。今の簡素なタイトルは変える。
- 住みごこちの色は現行の色を継続（未登録 #E0E0E0 / 最高 #FF4D4D / めちゃイイ #FF8C42 / ちょっといい #FFD93D / ふつう #6BCB77 / びみょう #4D96FF / すみかなし #BFBFBF）。
- ファビコン: メタモン。

### 5.2 アイコン画像
- アイコンは見切れないこと（現状のPokeAPI画像は周囲に透明な余白があり、拡大すると見切れる）。
- 通常のポケモン: PokeAPI のスプライト（`sprites/pokemon/{全国図鑑番号}.png`）を **一度ダウンロードし、透明な余白を切り取って、プロジェクト内に保存** して使う。
- 特別な姿（モジャンボ(はかせ)、カビゴン(こけむし) など公式画像がないもの）と、ユーザーが用意したゲーム内アイコン: プロジェクト内で管理し、**こちらがあれば優先** して表示する。
- ゲーム内アイコンは、ユーザーがゲームの「ポケモンずかん」画面のスクショを共有 → Claude が切り抜く。ずかんは番号順なので、位置から番号を割り出し登録データと照合し、見た目でも確認。怪しいものはユーザーに確認する。（この切り抜き作業は本設計の実装後に別途行う。実装はその画像を置けば差し替わる仕組みまで）
- 画像の用意が無いポケモンは、プレースホルダ（シルエット等）を表示。
- pocoapoke の番号（`number`）はゲーム内の図鑑番号で、全国図鑑番号ではない（例: 13番ナゾノクサ＝全国43番）。名前→全国図鑑番号の対応表が必要。
- **同じ番号でも姿が違うポケモンがいる**（ユーザー指摘）。既存通り、同じ番号で別のマスタ（`pokemon_ms` の行）を持ち、**アイコンも姿ごとに別**。そのため、アイコンは番号ではなく `pokemon_ms.id`（行）ごとに割り当てる。
  - 現在の該当: 41 モジャンボ／モジャンボ(はかせ)、59 カラナクシ(にしのうみ／ひがしのうみ)、60 トリトドン(にしのうみ／ひがしのうみ)、79 ピカチュウ／ピカチュウ(うすいろ)、108 カビゴン／カビゴン(こけむし)、145 シャリタツ(たれたすがた／そったすがた／のびたすがた)、197 ストリンダー(ハイ／ロー)。番号の重複はないが姿付きの名前: ウパー(パルデア)、ドーブル(ペインター)、ロトム(ステレオ)、ヨクバリス(シェフ)、デカヌチャン(おやかた)。
  - 公式に別の姿の画像がある姿（にしのうみ／ひがしのうみ、パルデアのすがた、シャリタツの3つの姿、ストリンダーのハイ／ロー など）は、PokeAPI の姿別スプライトを使う。どの姿がどの画像かは実装時に PokeAPI のデータで確認し、**判断がつかないものはユーザーに確認する**（推測で割り当てない）。
  - ぽこあポケモン独自の姿（はかせ、うすいろ、こけむし、ペインター、ステレオ、シェフ、おやかた）は公式画像がないため、ユーザー提供の画像を置くまでは元のポケモンの画像で代用する。

### 5.3 住みごこち画面（Progress, モックの「住みごこち（C案・改）」）
- 上部: 「住んでる街」チップ（横スクロール）で絞り込み。**先頭に「未登録」チップ** を置き、街が未登録のポケモン（新規登録直後など）はそこに表示する。
- **最後に選んだ街を覚えておき**、次に開いたときもその街を選んだ状態で表示する（ブラウザ内の保存でよい）。
- 表示切り替え: 「住みごこち順」（デフォルト）／「番号順」。
  - 住みごこち順: 住みごこちごとに色付き見出しでグループ化し、**低い順**（未登録 → すみかなし → びみょう → ふつう → ちょっといい → めちゃイイ → 最高）に並べる。
  - 見出しをタップでそのグループを開閉。**「最高」はデフォルトで閉じた状態**。
  - 見出しには「お世話 x/y」を表示。
  - 番号順: グループなしの一覧。各行に住みごこちのバッジを表示。
- 上部に「今日のお世話 x/y」。
- 各行: アイコン、名前、**好きな味（固定）→ 欲しいもの（可変）の順** のタグ、右端にお世話チェック □。
- チェック: □ を手動でタップしたときだけ付く／外れる。保存され、再読み込みしても状態は残る。手動で外した場合も外れたまま残る。□ は誤タップしにくい大きさ・間隔にする。
- 行をタップ → 下から出るパネル（ボトムシート）で以下を変更し「保存」:
  - 住みごこち（6択）
  - 今日の欲しいもの: **そのポケモンの好きなもの（味以外の5種）＋「なし」** から選ぶ。（ゲーム仕様が違うと分かったら別途修正）
  - **住んでる街**（未登録＋6つの街）。ゲーム中に引っ越しさせたとき、その場で直すため。変更すると今の絞り込みからは外れる。
  - 保存してもチェックは付かない（アンチゴール参照）。
- ボトムシートはグループ見出しより前面に表示する（モック初版のバグ）。
- **お世話チェックと欲しいものは、ゲームの日付が変わる毎朝 4:00（日本時間）にリセット**。
- **住みごこち画面に表示しないポケモン**: モジャンボ（※「モジャンボ(はかせ)」は表示する）、カイオーガ、ルギア、ホウオウ、メタモン。名前を直書きせず、ポケモンデータの「住みごこち画面に表示」設定で管理し、編集画面で切り替える。
- 今の「欲しいものを一括クリア」ボタン（`clearAllWish`）は自動リセットになるため削除。

### 5.4 一覧画面（List, モックの「一覧（List）案」）
- 見る専用。カードをタップすると編集画面へ。
- 並び順: 番号順（進化ラインが並ぶ）。
- 上部の街チップに **各街の住民数** を表示（「すべて」もあり）。タップでその街に絞り込み。
- 絞り込み: 好きな環境、好きなもの、得意なこと（ボトムシートで選択）。一致したタグを青く強調。
- カード: アイコン、No.、名前、好きな環境・得意なことのタグ、住んでいる街（略称）、好きなもの5つ＋味。
- **「似た好みを探す」**: カードのボタンから、そのポケモンと **好きなもの（味以外の5つ）が重なる数が多い順** に他のポケモンを表示。各ポケモンの街と、重なっている好きなものを表示。上部に「街ごとの相性」（各街に重なりのあるポケモンが何匹いるか）を表示。味は数えない。

```
ゼニガメ と好みが近いポケモン
──────────────────────────
街ごとの相性  ドンヨリ ●●● 3匹 / ゴツゴツ ● 1匹
──────────────────────────
[img] カメール   ドンヨリ   ★3  水を感じる・せいけつ・キズをいやす
[img] ヤドン     ドンヨリ   ★3  水を感じる・せいけつ・キズをいやす
[img] イーブイ   パサパサ   ★2  キュート・みんなで使う
```

### 5.5 編集画面 / 登録画面（モックの「編集画面」「登録画面」）
- 編集画面は登録画面と同じレイアウト（現在の `/edit/:id` の仕組みを継続）。一覧のカードから遷移。
- 項目ごとに白いカードで区切る。チップは親指で押しやすい大きさ。
- 上部: アイコン（名前から自動）、カテゴリ（DLC/EX/本編）、番号、なまえ。
- 得意なこと1（必須）/2、好きな環境、好きなもの（最大5、残数表示）、好きな味。
- **住んでる街**（未登録＋6つの街）。一覧で引っ越し先を決める流れからそのまま変更するため。住みごこち画面のパネルと同じ値を変更する（ユーザー決定: 両方に置く）。登録画面にも同じ欄を置き、既定は「未登録」（Claudeの判断）。
- 編集画面のみ: 「住みごこち画面に表示」スイッチ。
- 「更新する」「登録する」ボタンは画面下に固定。編集は「一覧に戻る」、登録は「リセット」を併置。
- 登録時の番号の自動採番など、現行の挙動は維持。

## 6. データとAPIの変更（決定事項＋Claudeの提案でユーザー了承済み）

- お世話チェック: `pokemon_status` に「最後にお世話した日（ゲーム日付）」を保存。表示時に「今日のゲーム日付」と一致すればチェック表示。手動で外したら空にする。日付比較だけなので、リセット用の一括処理は不要。
- 欲しいもの: 値と「入力したゲーム日付」を保存し、今日のゲーム日付でなければ空として扱う。
- ゲーム日付 = 日本時間で現在時刻から4時間引いた日付（4:00切り替え）。
- 住みごこち画面に表示するか: `pokemon_ms` に表示フラグ列を追加（既定は表示）。上記5体を非表示で初期設定。
- 欲しいものの値は「好きなもの」マスタ（`master_code` class=favorite）のIDになる。現行の `today_wish` は wish/environment/category を選べる形だが、新しい選択肢は好きなもの5種＋なし。
- 住んでる街を編集・登録画面から変更できるようにするため、編集・登録のAPIは `pokemon_status.place_code` も書き込む（現行の `updatePokemon` は pokemon_status を変更しない作りなので変更が必要）。

### 6.1 本番反映の手順（ユーザーが手元で実行）
この作業環境からは push も Cloudflare へのログインもできないため、以下はユーザーが手元のターミナルで実行する。計画には各ステップのコマンドと確認方法を書くこと。
1. 本番D1のバックアップ（`wrangler d1 export --remote` など）
2. 列追加のマイグレーションを本番D1に適用（`wrangler d1 execute --remote`）し、確認
3. データ・API変更を push（旧画面のまま動くことを確認）
4. 新しい画面一式を push（本番で4画面を確認）

### 7.1 Claude が決めた点（ユーザー確認用）
- 新しい「欲しいもの」は新しい列に保存する（現行 `today_wish` は NOT NULL で wish マスタを指しており、データ先行リリース中も旧画面を動かすため）。
- 一覧の番号順は既存の `src/lib/pokemonOrder.ts`（本編→EX→DLC）を使う。
- 住みごこち画面に表示しないポケモン（メタモン等）も、一覧には表示し、街の住民数と「似た好みを探す」にも含める。
- アイコンの優先順位: ユーザー提供の画像（ゲーム内アイコン・特別な姿）→ 余白を切り取ったPokeAPI画像 → プレースホルダ。
- 登録画面にも「住んでる街」欄を置く（既定は未登録）。
