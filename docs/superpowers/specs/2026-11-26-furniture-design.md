# 家具さがし 設計書

- 日付: 2026-11-26
- 対象リポジトリ: `Hiroki-Ko/pocoapoke`（React 19 + Vite + Tailwind v4 / Cloudflare Pages Functions / D1）
- 規模: プロジェクト（新しい画面 + 家具データの収集）

## 1. 目的と背景

すみかに家具を置くとき、そこに住むポケモンの「好きなもの」に当てはまる家具を効率よく見つけたい。
家具ごとの属性（＝好きなもののカテゴリ。木製、やわらかい など）はゲーム内で確認する方法がなく、数も多いため、Claude がネットから集めてアプリに入れる。

### 使う場面（ユーザーの言葉から）
- すみかに家具を置くときに使う。アイテム交換や素材のためには使わない
- 1つのすみかに複数のポケモンが住むことがある。進化ラインを1つの家にまとめる、すみか同士を近くに置くなど、家具を共有する機会が多い

## 2. ゴール / 非ゴール / アンチゴール

### ゴール
- 家具の一覧を、ポケモン一覧と同じようなカード（画像・名前・属性チップ）で見られる
- 属性で家具を絞り込める
- 属性から「その属性が好きなポケモン」を逆に探せる
- 1匹〜複数のポケモンを選ぶと、好きなものに多く当てはまる家具から順に並ぶ。カードに「誰の、どの好きなものに当てはまったか」が出る

### 非ゴール
- 素材・ブロック・食べものなど、すみかに置かないアイテムの収録
- アイテム交換の価値計算
- 持っている家具の記録、アプリからの家具データの登録・編集（家具データは読み取り専用）
- レシピ・入手場所の表示

### アンチゴール（動いても失敗とみなすもの）
- 家具の名前がゲーム内の日本語名と違い、ゲームで探せない
- 属性の抜け・間違いが多く、結果が信用できない
- ゲーム中に片手で使うには操作が多すぎる（今のアプリより重い・遅い）

## 3. 制約
- スマホ（Android の Chrome、インストール版あり）での利用が中心。今の画面とデザインをそろえる（黄色ヘッダー、カード、下のタブバー）
- `git push` と本番 D1 のコマンドはユーザーが実行する。今回は D1 を変えない
- 好きなものの名前・コードは今の `master_code`（class=favorite、code 6〜48 の 43 種類）に合わせる。味（code 1〜5）は家具に関係しない
- データの出所:
  - Game8（日本語）は「データの無断使用・無断転載」を禁止しているので、まとめて取り込まない
  - 属性: Serebii の「Favorites」ページ（43 カテゴリそれぞれに当てはまるアイテム一覧、英語）を中心に集める
  - 日本語名: op.gg の日本語ページ（`op.gg/ja/pokemon-pokopia/items`、英語スラッグ ↔ 日本語名）。Bulbapedia の各アイテムページ（日本語名・属性あり、CC BY-NC-SA）も照合に使える
  - Claude のクラウド環境・PC の Linux 環境からは、これらのサイトへ curl できない（WebFetch とブラウザ操作は可）
- 画像はゲームの画像。今のポケモンアイコンと同じく個人の非営利アプリでの利用として扱い、出典を画面に書く

## 4. 作り方の候補と決定

| 案 | 内容 | 良い点 | 弱い点 |
|---|---|---|---|
| **A（採用）** | 家具データを `src/data/furniture.json` としてアプリに入れる。画像は `public/furniture/` | DB 変更・本番 D1 コマンド不要。更新はコミットと push だけ。読み取り専用のデータに合う | スマホから家具データを直せない（Claude に頼む） |
| B | D1 に家具テーブルと属性テーブルを作り API で返す | 将来「持っている家具」などアプリから書き込む機能を足しやすい | migration と本番へのデータ投入が必要。直すたびに SQL |

ユーザーが A を選んだ。理由: 家具の情報はゲームの事実で、アプリから変えるものではないため。

## 5. 決まったこと（ユーザーが決めたもの）
- 案 A（JSON ファイル）
- 対象はすみかに置ける家具・屋外アイテムのみ
- 一覧のカードに家具の画像と属性を出す
- 複数のポケモンで探せるようにする
- 画像がネットで手に入らない家具は、ユーザーがゲームのスクショを共有できる（予備）

## 6. 設計

### 6.1 データ: `src/data/furniture.json`
```json
[
  {
    "slug": "stylish-stool",
    "name": "オシャレなこしかけ",
    "en": "Stylish stool",
    "tag": "relaxation",
    "favorites": [15, 17, 31, 39, 47, 45],
    "image": "stylish-stool.png"
  }
]
```
- `slug`: 英語名を小文字・ハイフンつなぎにしたもの（op.gg のスラッグと同じ）。一意のキー
- `name`: ゲーム内の日本語名。画面にはこれを出す
- `tag`: Serebii の分類（decoration / relaxation / toy / food / road / outdoor など）。画面の並び替え・絞り込みの補助
- `favorites`: `master_code` の favorite の **code**（id ではない。D1 ごとに id が変わり得るため）
- `image`: `public/furniture/` のファイル名。無ければ `null`
- 英語カテゴリ名 → code の対応表は `scripts/furniture/favorite-map.json` に置く（例: "Wooden stuff" → 45 木製）
- 家具ページは `import()` で遅れて読み込み、最初の画面の読み込みを重くしない

### 6.2 データの集め方（Claude が行う）
1. Serebii の 43 カテゴリのページから「アイテム → 当てはまるカテゴリ」を集める（WebFetch）
2. すみかに置かないもの（Serebii で分類が無いもの＝素材など、ブロック、キット）を外す
3. op.gg の日本語の一覧（「すべて表示」で全件）から日本語名を対応づける。Claude in Chrome かアプリ内ブラウザで読む
4. 日本語名が見つからない・属性が空のものは Bulbapedia の個別ページで確認する
5. 確認用に `scripts/furniture/review.csv`（日本語名・英語名・属性・画像の有無・出所）を作り、ユーザーに見せる
- 収集の途中結果は `scripts/furniture/raw/` に保存し、やり直せるようにする

### 6.3 画像
- 画像の URL 一覧（slug → URL）を JSON にしておき、ユーザーが PC の PowerShell で `node scripts/furniture/download-images.mjs` を実行して取得する（ユーザーの PC は普通にネットにつながるため）
- スクリプトは sharp で周りの透明な余白を切り、`public/furniture/<slug>.png` に保存。既にあればスキップ
- 取れなかったものは一覧を出す。ユーザーのスクショから切り抜く（`pocoapoke-add-icon` スキルと同じ手順）か、画像なしのカードにする

### 6.4 画面: 家具タブ（`/furniture`）
- 下のタブバーに「家具」（🪑）を追加し、4 タブにする（一覧 / 住みごこち / 家具 / 登録）
- ヘッダー: 見出し「家具さがし」、説明「好きなものに合う家具をさがす」、右に件数
- ヘッダーの下に 2 つの切り替え: **家具から** / **ポケモンから**

**家具から（一覧）**
```
[名前で検索______] [属性 ▼]
┌──────────────────────────────┐
│ [画像] オシャレなこしかけ         │
│        カラフル キュート 布仕立て …  │
└──────────────────────────────┘
```
- 名前の部分一致検索と、属性の絞り込み（今の一覧画面の FilterSheet と同じ操作。1 つ選ぶ）
- 絞り込み中の属性はチップを青く強調
- カードの属性チップをタップ → 下からパネルが出て「〇〇が好きなポケモン」一覧（アイコン・名前・住んでる街。番号順）

**ポケモンから**
```
[街: パサパサ ドンヨリ …]
□ ピカチュウ  □ ライチュウ  ☑ フシギダネ …   （選んだ数: 2）
────────────────
┌──────────────────────────────┐
│ [画像] まるたのいす     ★ 4       │
│   木製 自然を感じる まんまる        │
│   (フシギダネ)木製 自然  (フシギソウ)木製 まんまる │
└──────────────────────────────┘
```
- 街で絞ってポケモンにチェックを付ける（未登録の街も選べる）。選んだポケモンは上に小さなアイコンで並べ、タップで外せる。上限は設けない
- 並び順: 「選んだポケモンの好きなもの（各 5 つ、味は除く）と家具の属性が当てはまった数」の合計が多い順 → 当てはまった好きなものの種類が多い順 → 日本語名順
- 当てはまりが 0 の家具は出さない
- カードには、当てはまった属性を強調し、ポケモンごとに小さなアイコンと当てはまった属性を出す
- 選んだポケモンはこの画面にいる間だけ覚える（保存しない）

**他の画面からの入口**
- 住みごこち画面のパネル（ProgressSheet）に「家具をさがす」ボタンを置き、そのポケモンを選んだ状態で「ポケモンから」を開く（`/furniture?poke=<id>`）

### 6.5 コード
- `src/lib/furniture.ts`: 順位づけ（`rankFurniture(items, pokemon[])`）、属性→ポケモン（`pokemonWhoLike(code, pokemon[])`）。vitest でテスト
- `src/pages/Furniture.tsx`、`src/components/FurnitureCard.tsx`、`src/components/FurnitureIcon.tsx`（画像なしのときは家具っぽい灰色の枠）
- ポケモンのデータは今の `usePokemonData` を使う

### 6.6 出典の表示
- 家具ページの一番下に「家具データ: Serebii.net、op.gg、Bulbapedia（CC BY-NC-SA）を参考に作成。画像 ©Pokémon / Nintendo / Creatures / GAME FREAK / KOEI TECMO GAMES」
