# pocoapoke デザイン一新 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** スマホ基準の新デザイン（Tailwind）で住みごこち・一覧・編集・登録の4画面を作り直し、アイコン表示・お世話チェック・欲しいものの4時リセット・似た好み検索を加える。

**Architecture:** 先にD1の列追加とAPI拡張だけを本番へ出し（旧画面は動き続ける）、その後MUIを外してTailwindで4画面を作り直して一度に切り替える。日付・グループ化・類似度・アイコン解決などのロジックは `src/lib/` の純関数にして Vitest で検証し、APIはローカルの `wrangler pages dev` と curl で検証する。アイコンはPokeAPIのスプライトを事前にダウンロード・余白トリムして `public/icons/` に置く。

**Tech Stack:** React 19, Vite 5, TypeScript, @tanstack/react-query, react-router-dom 7, Tailwind CSS v4（`@tailwindcss/vite`）, Vitest, sharp（アイコン生成スクリプトのみ）, Cloudflare Pages Functions + D1, Playwright（画面確認）

**Spec:** `docs/superpowers/specs/2026-11-25-redesign-design.md`

## Review Focus

1. **端末の時計・タイムゾーンが日本以外、または 3:59/4:00 の境目** → ゲーム日付は常にJST基準で、4:00ちょうどで翌日に切り替わる。（Task 1 のテスト）
2. **`pokemon_status` 行が無いポケモン** → 一覧・住みごこち画面で落ちずに「未登録」の街・住みごこちとして表示され、保存すると行が作られる（UPSERT）。（Task 2, Task 6 のテスト）
3. **好きなものが5つ未満、または欲しいものが編集後に好きなものから外れた** → 選択肢は登録済みの好きなものだけ。既に保存された欲しいものはラベルをそのまま表示。好きなもの以外のIDを送るとAPIが400。（Task 2, Task 6）
4. **アイコンが無い名前（新しく登録した独自の姿・表記ゆれ）や画像の読み込み失敗** → 壊れた画像ではなくプレースホルダを表示。（Task 4 のテスト）
5. **チェックや保存の通信失敗・連打** → 画面の状態を元に戻し、エラー通知を出す。チェックの連打で最終状態とサーバーがずれない。（Task 6 の手動確認）
